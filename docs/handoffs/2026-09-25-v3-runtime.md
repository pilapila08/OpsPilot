## 已接受决策与兼容性

- **ADR 0006**：运营 Trace 只进本地 CLI。HTTP API 无认证，未新增 `/trace`。不展示模型/Tool 原始请求与输出、Prompt 正文、provider 异常原文或 Evidence 正文。
- **ADR 0007**：六维准入统一；模型失败仍记录 usage。tokens/cost 响应用量无法预知，最多一次响应观测跨限后停止，当前没有精确成本预留。
- Run 终态仍是 `BUDGET_EXCEEDED`；其 Result 为 `PARTIAL`，不是丢失结果的崩溃。`BudgetVerificationV3(kind=budget_stop)` 无 Claim、`supported=false`，允许零 Evidence；没有削弱冻结 V1/V2 Verification。
- step 按逻辑 Tool 首次尝试计数；tool_calls 按每次尝试；重生成与 Tool 重试共享 retries。工具重试/完成的 stop.step_no 指当前步骤，Planner 指下一待执行步骤。
- BudgetStop、Result、最终 Run 分次提交。进程或存储中途失败时，可能只有停止事实；尚无崩溃恢复编排。同步存储/验证不保证截止瞬间被中断。
- SQLite Trace 使用只读连接，不创建缺失库、不隐式迁移。旧库须先 upgrade head；Demo/API 是显式执行迁移的入口。
- InMemoryModelAuditRepository 单独使用时须 `bind_run_trace(run_id, trace_id)` 或构造时提供映射；SQL 通过 Run 关联，无需调用方绑定。

## 本机可重复的运行方式

在仓库根目录，Python 3.12/3.13：

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -e ".[dev]"
opspilot demo
opspilot demo --scenario oom
opspilot demo --scenario oom --max-steps 1
opspilot trace <上次输出的trace_id> --database ./var/demo.db --json
python -m pytest -q
python -m mypy
```

- Demo 不需要密钥或集群。默认独立 `var/demo.db`，每次新 Run；CrashLoop 为 3 LLM / 4 Tool / 四类五条 Evidence，OOM 为 5 LLM / 4 rounds / 3 Tool / 五条 Evidence。
- OOM `--max-steps 1`：下一 Planner 前停止，已有两条 Evidence，schema 3 PARTIAL；CrashLoop `--max-steps 3`：整份计划执行前拒绝，无 Evidence 也有 PARTIAL。
- Demo 的成本/延迟/token 是零或固定离线示例，不是付费推理指标。OOM 观察使用 fixture 回放时钟；数据库创建/LLM 审计时间是当前实际时间，elapsed 是实际耗时。不要把它们当作 Live 全局时间线。
- 退出码与六维参数见 `docs/development.md`。当前只保证源码 editable 安装；fixtures/prompts/migrations 尚未做自包含 wheel 打包。
- 本机 API 已更新到本次代码和迁移 0005，绑定 `127.0.0.1:8000`、Live 关闭。`POST /diagnosis` Replay 实跑 COMPLETED、5 条 Evidence、supported=true。后台 PID/日志在忽略的 `var/opspilot-api.*`；进程结束后按 development 文档启动即可。
- 此次没有真实 Kubernetes/Prometheus/GitHub Live 执行，没有公共云部署；历史 Live 验收不当成本机本次验证。
